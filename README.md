# ChemAI: Predict the Cure — Team 38

Решение хакатона МИФИ «**ChemAI: Predict the Cure**» — задачи по
предсказанию биологической активности химических соединений против вируса
гриппа. Для каждого соединения нужно предсказать три параметра:

| | расшифровка | свойство |
|---|---|---|
| **IC50, mM** | концентрация, при которой подавляется 50% активности вируса | чем меньше, тем эффективнее |
| **CC50, mM** | концентрация, при которой вещество токсично для 50% клеток  | чем больше, тем менее токсично |
| **SI**       | Selectivity Index = `CC50 / IC50` | чем больше, тем лучше профиль |

Метрика — **RMSE, усреднённый по трём таргетам**.
Соревнование: <https://www.kaggle.com/competitions/chem-ai-predict-the-cure>

## Результат

| Версия | Подход | OOF composite | Public LB |
|---|---|---|---|
| v0 | Исходные Colab-ноутбуки (baseline команды) | 311.80 | 316.00 |
| v1 | Рефакторинг + ансамбль 3 бустеров + leak-safe CV | 309.44 | 313.10 |
| v2 | + Optuna HPO + взвешенный ансамбль | 308.72 | 312.66 |
| **v3** | **+ Huber loss на raw target + SI как ratio + clipping** | **280.88** | **TBD** |

Главный технический рычаг — **смена loss-функции с log1p MSE на Huber loss
на raw таргете**. Это выровняло оптимизируемую функцию с метрикой
соревнования и дало −27.8 пункта на composite OOF за одну архитектурную правку.

## Быстрый старт

Требуется [`uv`](https://docs.astral.sh/uv/) и Python 3.14+.

```bash
# 1. Установка
uv sync

# 2. Положить данные (закрытые, по ссылке из условия хакатона)
mkdir -p data/raw
cp ~/Downloads/train.csv  data/raw/
cp ~/Downloads/test.csv   data/raw/

# 3. Тренировка (3 seeds × 5 folds × {CatBoost, LightGBM, XGBoost})
uv run python -m src.train --n-seeds 3 --n-splits 5

# 4. Сборка submission
uv run python -m src.predict --si ratio --out submissions/submission.csv
```

Полный прогон: ~10 минут на 8-ядерном ноутбуке.

Опциональный шаг — поиск гиперпараметров через Optuna (~1 час):

```bash
bash scripts/run_full_hpo.sh
```

После него `src.train` автоматически подхватит `artifacts/best_params/*.json`.

## Подход

### Данные

- Train: 751 строка × 214 колонок. После дедупликации (181 точных дубликата
  по фичам с разными измерениями таргетов → медиана) — **628 уникальных молекул**.
- Test: 250 строк × 211 колонок (нет IC50/CC50/SI).
- 210 общих фичей: RDKit-дескрипторы — `MaxEStateIndex` … `fr_urea`. Включают
  общие свойства (MolWt, MolLogP, TPSA), электронные (PEOE_VSA*, partial
  charges), топологические (Chi*, Kappa*, BalabanJ), VSA-поверхностные
  (SMR_VSA*, SlogP_VSA*), функциональные группы (fr_*) и Morgan-плотности
  (`FpDensityMorgan*`). SMILES-структур в данных нет — пересчитать фингерпринты
  нельзя.
- 24 NaN-ячейки в трейне, 12 в тесте — заполняются медианой.

### Особенности таргетов

| target | mean | median | max | skew | значение |
|---|---|---|---|---|---|
| IC50 | 216 | 56 | 4095 | 3.53 | сильно скошено вправо |
| CC50 | 565 | 448 | 4539 | 2.28 | скошено, но мягче |
| SI | 25 | 4 | 1619 | **11.3** | экстремальный хвост |

`|SI − CC50/IC50| ≈ 5.9e-14` в трейне — то есть SI **арифметически выводится**
из других таргетов с точностью float64. Это не «отдельная переменная», как
говорит условие, а функция от двух других.

### Препроцессинг (leak-safe)

Всё, что имеет состояние, упаковано в `sklearn.Pipeline`, фитящийся **внутри
каждого CV-фолда**. Шаги:

1. **`SimpleImputer(strategy='median')`** — заполняет 12 колонок с пропусками
2. **`VarianceThreshold(0)`** — выбрасывает ~18 константных признаков
3. **`StandardScaler`** — нормализация для PCA/KMeans
4. **`CorrelationFilter(threshold=0.98)`** — выбрасывает один из каждой пары
   с `|corr|>0.98` (около 37 признаков)
5. **`UnsupervisedFeatureExpander`** — добавляет:
   - 40 главных компонент PCA
   - метку кластера (12 KMeans)
   - 12 расстояний до центров кластеров

Итог: **~226 признаков** (вместо начальных 210).

Главный отход от исходного Colab-кода: всё это было фитово на полном трейне
**до** CV-сплита. То есть валидационные данные косвенно влияли на параметры
скейлера/PCA — слабая, но реальная утечка. У нас Pipeline фитится только на
тренировочной части каждого фолда.

### Loss-функция: главный технический выбор

**Метрика Kaggle — RMSE на raw-таргете**, но скошенные таргеты обычно
тренируют на `log1p(y)` для стабильности. У этой стандартной схемы есть
тонкая проблема:

> Тренировка на `log1p(y)` минимизирует **относительную** ошибку, а Kaggle
> мерит **абсолютную**. На тяжёлых хвостах две оптимизации расходятся:
> log-loss «жалеет» большие значения (тысячи в raw — это всего 7 в log),
> а raw RMSE именно их и штрафует.

Диагностика показала, что наш log1p-ансамбль был всего на 15 пунктов лучше
константного предсказания `mean` на IC50 (344 vs 359), и на 2.2 пункта
лучше константы на SI (105 vs 107). То есть log1p модели «не учат» хвосты.

**Решение — Huber loss на raw таргете:**

| Модель | Активация в huber_raw mode |
|---|---|
| CatBoost | `loss_function='Huber:delta=K'` |
| LightGBM | `objective='huber', alpha=K` |
| XGBoost  | `objective='reg:pseudohubererror', huber_slope=K` |

`δ = IQR(y) / 2` — robust-статистика; автоматически: 119 для IC50, 382 для CC50.
Huber квадратичен на `|residual| < δ` (как MSE) и линеен на `|residual| > δ`
(как MAE). Это:

- оптимизирует **ту же** функцию потерь, что метрика Kaggle (raw RMSE)
- не разносится одиночными выбросами (бустинг под чистым MSE может выгореть
  на одной строке с CC50≈4500)

Эффект: composite OOF упал с 308.72 (log1p) до 280.88 (Huber raw) — самое
большое улучшение по всему пайплайну.

### Стратегия для SI

Изначально мы пробовали три:

1. **model** — отдельная модель на `log1p(SI)`
2. **ratio** — `SI_pred = clip(CC50_pred / IC50_pred, 0, p99_SI)`
3. **blend** — `α·model + (1-α)·ratio` с подбором α по OOF

Диагностика на v2:

- модель SI давала OOF RMSE = 105.0
- const=mean baseline = 107.1 (выигрыш 2.0 пункта)
- top-1% строк давали **88%** всего squared error модели

То есть модель SI училась предсказывать примерно константу. Топ хвоста
(SI > 1000) не предсказуем из дескрипторов — это редкие соединения, у которых
крошечный IC50 (≈0.003 mM) дал гигантский ratio.

В v3 **отдельная модель SI отключена**. SI собирается из ratio с клиппингом
на `p99(train_SI)`. Это:

- экономит 33% компьюта (треть таргетов не тренируется)
- даёт OOF RMSE 108.3 — фактически на уровне модели (~−3 пункта), но согласуется
  с предсказаниями CC50/IC50 по тождеству

### Clipping предсказаний

После всех преобразований предсказания каждого таргета зажимаются на
`[0, p99(train_y)]`:

```
IC50:  [0, 1306]  (train max = 4095, p99 ≈ 1306)
CC50:  [0, 2835]  (train max = 4539, p99 ≈ 2835)
SI:    [0, p99]   (train max = 1619)
```

Зачем: бустинговые модели иногда экстраполируют выше любых train-значений
из-за random forest-aggregation в листьях. Если на тесте мы выдадим
предсказание 10000 при истинном значении 4000, ошибка возводится в квадрат
и катастрофически портит RMSE. Если же мы зажмём на 2835 — потеряем правду
в одном-двух экстремальных случаях, но не получим катастрофу на остальных.
`p99` фиксирован при тренировке и сохраняется в `artifacts/clip_bounds.json`.

### Модели и ансамбль

Для каждого таргета (IC50, CC50) обучается **три бустера**: CatBoost,
LightGBM, XGBoost. Гиперпараметры тюнятся через Optuna (`src/tuning.py`):

- 40 trials для CC50 (главный рычаг скора)
- 30 trials для IC50
- 20 trials для SI (если её всё-таки тренируем)
- KFold(3) внутри trial — TPE-сэмплер из Optuna

`KFold(5, shuffle=True) × 3 seeds (42, 77, 112) × early_stopping=300` —
production-CV. Предсказания усредняются по фолдам и seed-ам внутри каждой
модели, затем три модели взвешиваются как `w_i = (1/RMSE_i) / Σ(1/RMSE_j)`.

В практике после Huber loss модели стали почти равноточны (RMSE 310–319 на
IC50, 422–430 на CC50), и веса все ≈0.33. Главный выигрыш дал именно
выбор loss, а не выбор модели.

### Воспроизводимость

- `src/seeds.py::set_seed(42)` фиксирует `PYTHONHASHSEED`, `random`, `numpy`.
- Все бустеры принимают `random_seed`/`random_state`, разные на фолд для
  диверсификации внутри ансамбля, но детерминированные относительно глобального seed.
- `n_init=20` для KMeans — стабильный фит.
- `uv.lock` фиксирует все версии пакетов.
- Препроцессор фитится **только** на train-части фолда — никаких утечек.
- Все артефакты (`oof_*.npy`, `test_*.npy`, `cv_report.json`, `clip_bounds.json`)
  сохраняются в `artifacts/`. `predict.py` собирает submission из них без
  повторного обучения.

## Что НЕ сработало / Lessons learned

1. **Optuna HPO дал всего −0.72 пункта на composite OOF.** Найденные гиперы
   улучшили per-trial RMSE на KFold(3), но не генерализовались на KFold(5):
   IC50 показал HPO=329 vs production=343 — разрыв 14 пунктов. На маленькой
   выборке (628 строк) KFold(3) в HPO слишком оптимистичен.

2. **Сложный ансамбль из 3 бустеров на log-loss дал ~1 пункт сверх CatBoost-only.**
   После Huber разница между бустерами тоже маленькая (~5 пунктов). Loss-функция
   повлияла в **30 раз сильнее**, чем выбор модели или гиперпараметры.

3. **Отдельная модель SI — пустая трата компьюта.** Она училась предсказывать
   константу. На таком тяжёлом хвосте (skew=11.3) — это нормальное поведение
   для бустинга, который усредняет листья.

4. **Корреляционный фильтр для деревьев не нужен.** Сейчас выбрасываем ~37
   признаков с `|corr|>0.98`, но GBDT не страдает от мультиколлинеарности —
   возможно, это даже отнимает сигнал. Не пробовали отключать, но в будущей
   итерации можно проверить.
